# 数え方の限界（正直な話）

このアプリの自動カウントは概算のための道具です。誤差の大きさは実機未検証のため **分からない** と明記します。分かるのは、どういう場面で間違えるかです。

## 自動で数える仕組みの前提

- 大津二値化は「背景と物の明暗がはっきり分かれる」前提で、閾値は画像全体で1つだけです
- 失敗パターン:
  - 物同士がくっついている／重なっている → 1個に数える
  - 影が物とつながる → 形が崩れて誤カウント
  - 背景に模様がある → ノイズを数える（下限面積スライダで緩和）
  - グラデーション照明 → 端の物を取りこぼすことがある
  - 物の中に明暗の大きな模様がある → 1個が複数に割れることがある

## ライブで数える

- 写真モードと同じ限界に加えて、表示を安定させる平滑化（直近7フレームの中央値）の分、個数が変わってから表示が追いつくまで最大で数フレーム遅れます
- 手ブレや照明のちらつき（蛍光灯のフリッカなど）で検出が揺れます

## 通過カウント

- 重心の最近傍追跡なので、物同士が線の近くですれ違う・重なると、対応付けを間違えて数え漏らしや二重カウントが起きます
- 線の内側（デッドバンド）で現れた／消えた物は数えません。出自・行方が分からないためです
- 数フレーム以上検出から消えた物は別物として扱います。一時的に隠れた物が線の向こうで再出現すると、横切りを数えません
- カメラが動くと全景が動いて誤検出します。固定して使ってください

## 手動の数え方

- タップ数えと手動カウンターは、押した回数そのものが数です。機械側の誤差はありません（押し間違いはあります）

## 総論

- 実機での検証（実際に数えた個数との突き合わせ）は今後の課題です
- 「だいたいの個数がその場で分かる」用途に限って使ってください
