# 精度について（正直な限界）

このアプリは概算のための道具です。モードごとの誤差要因を隠さず書きます。

## 上下スキャン（二重積分）

- スマホの加速度センサはノイズとバイアスが大きく、二重積分では誤差が時間とともに増えます
- ZUPT と線形ドリフト補正で抑えてはいますが、誤差の大きさは実機未検証のため **分からない** です
- 悪化要因: 速い動き、途中で端末を傾ける（回転は補正しますが完全ではありません）、
  静止せずに開始／終了する、長い距離（積分時間が長いほど不利）
- 良くするコツ: ゆっくり一定速度で、開始と終了は 1 秒ほど静止する

## 傾けて測る（三角測量）

- 数学自体は正確ですが、入力が粗いです
  - カメラ高の入力誤差がそのまま効きます
  - 仰角は端末センサの精度に依存し、角度誤差は距離が遠いほど拡大します
  - 物体の下端が地面と接している前提です。段差があるとずれます
- 誤差の大きさは実機未検証のため分からない。遠距離では角度誤差が大きくなります（仰角の精度に依存）

## 静止画で測る

- 基準物と測る物が **同じ平面** にあるときだけ正しくなります
- 奥行きが違う場合、遠い物は小さく写るため実寸より小さく出ます（透視投影の性質）
- レンズの歪み（広角の周辺部）も誤差になります。中央付近で測るのが無難です
- タップ位置の誤差: 写真の解像度と指の太さが限界です

## 個数を数える

- 大津二値化は「背景と物の明暗がはっきり分かれる」前提です
- 失敗パターン:
  - 物同士がくっついている／重なっている → 1個に数える
  - 影が物とつながる → 形が崩れて誤カウント
  - 背景に模様がある → ノイズを数える（下限面積スライダで緩和）
  - グラデーション照明 → 閾値が全体で1つなので端の物を取りこぼす
- 手動モードは確実ですが、数が多いと大変です

## 総論

- 実測との比較検証（巻き尺との突き合わせ）は端末実機での今後の課題です
- 「だいたいの大きさ・個数がその場で分かる」用途に限って使ってください
